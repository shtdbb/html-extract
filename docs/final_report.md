# HTML 结构化抽取策略自进化——最终报告

> 项目：离线内容库网页字段抽取（title / content / authors / publish_time / update_time）
> 迭代区间：v4（上一阶段终态）→ v15（最终交付，git `3d1cb5e`）
> 硬件：Apple M4 Pro 64GB（统一内存，无独立显存）；模型：Qwen2.5-7B-Instruct Q4_K_M（本地 ollama）
> 术语约定：**规则管线**=站点规则库+元数据解析+trafilatura+DOM 回退的确定性链路（单页约 85ms）；**模型补全层**=规则输出低置信时方触发的本地大模型补全过程（约 2s/页），输出须经页内证据核验方可采纳；**误填**=标注为空而系统给值，**漏填**=标注有值而系统为空。
> 本文档配套：`loop/iteration_log.md`（逐轮日志）、`loop/metrics_history.jsonl`（机器可读指标流）、可视化网页（自进化全过程）。

## 1. 最佳方案总览（v15：规则管线优先 + 门控模型补全）

### 1.1 架构

```
                        ┌────────────────────────────────────────────┐
                        │              原始 HTML (bytes)              │
                        └──────────────────┬─────────────────────────┘
                                           ▼
                              ① 声明编码优先解码层
                                           ▼
                              ② trafilatura 预抽取 ─────────┐
                                           ▼                │（产出量供拒识信号）
                              ③ 拒识判定（结构信号）          │
                        空壳/列表页/图集 → 拒识记录           │
                                           ▼ 非拒识
                ┌──────────── ④ 三层候选产生 ────────────┐
                ▼                      ▼                  ▼
         站点规则库(3站)        元数据层(meta/json-ld)   trafilatura
         可 final 裁决空        og:/article:/name=      document.*
                └──────────────┬──────────────┬─────────┘
                               ▼              ▼
        ⑤ 字段级融合与后处理（规则 > final > 元数据 > traf > DOM 回退链）
         ├ title：回退链 → 品牌后缀剥离(中/英) → h1 整标题分歧优先(双守卫)
         ├ authors：媒体名/站名/垃圾署名三分过滤 → 署名扫描合并(强来源门控)
         ├ time：CMS 复制抑制 → byline 扫描补全 → EN 同日时分精化
         └ content：规则容器 → CMS 容器先验(门控) → traf body 树装配 → DOM 密度
                               ▼
        ⑥ 模型补全层（EXTRACT_MODEL=1，门控触发）
         ├ 门控：title 缺失/弱来源、authors 空、publish 空，且遵守 final 裁决
         ├ 单页单次调用合并抽取（Qwen2.5-7B，format=json，temperature=0）
         └ 三重核验：值须页内出现(规范化子串) / 署名须独立署名行+三分过滤 /
             时间须可解析+日期页内两级佐证 → 不通过即弃用，回退规则结果
                               ▼
                        结构化记录 + provenance
```

### 1.2 核心设计决策

| 决策 | 内容 | 出处 |
|---|---|---|
| 规则管线优先 | 85ms/页、零边际成本、可解释；模型只在规则失陷页触发 | v4-v9 |
| 门控模型补全 | dev 触发率 11%（10/89 页）、ISPRAS 约 40%；模型成本只在需要处付出 | v10 |
| 值必须页内可核验 | 模型只做「定位/摘录」，不做「生成」；幻觉在核验层被物理阻断 | v10 |
| final 裁决贯通 | 规则层判定「本站此字段不存在」时，模型同样禁止回退 | v10 修订 |
| 单调非负的精化 | 只升级时间精度、不新填日期——评分口径下不可能变差 | v15 |
| 每轮全量重跑+逐页回归 | 聚合分掩盖内部对冲（v12 首跑教训），逐页 diff 才能发现 | 全程 |

## 2. 评测设计

### 2.1 数据集

| 子集 | 构成 | 用途 |
|---|---|---|
| dev fixed 30 | 3 个规则站（news_cn/chinadaily/gov_cn）×10 | 规则库回归基准 |
| dev generic 55 | 11 个通用站×5（sina/sohu/people/ifeng/chinanews/cnblogs/segmentfault 等） | 通用路由调优唯一依据 |
| dev negative 4 | 频道列表页 | 拒识负例 |
| test 28 | 模板隔离预留（gmw 等未参与调优的站点族，含 8 个 photo_set 应拒识页） | 交付时一次性终测（--no-pages 聚合） |
| ISPRAS 外部基准 160 | 80 个英文站新闻页 | 跨语言/跨模板泛化验证（非调优集，但可驱动通用策略发现） |

### 2.2 评测纪律（全程未破）

1. 调优只看 dev；test 仅 v4 交付与本次终测各跑一次，且只读聚合；
2. 评分器 score_v2.py 冻结（49 项单测护住口径）；gold 不为分数回改——边界分歧一律挂起登记（cnblogs×11 项），而非修 gold 凑分；
3. 每轮策略改动 → dev 全量重跑 + 逐页回归 diff + git 提交（指标入 commit message）；回归即修复或回滚，全部留痕；
4. 模型输出必须可在页面文本/DOM 中核验——杜绝「分数好看但页面上不存在」的值。

### 2.3 指标设计（v2 冻结口径）

- **逐页宏平均**；失败永不离开分母（correct_empty 除外）——空 annotation 页猜空得分、猜错扣分；
- **title**：精确匹配 + title_sim 诊断量；
- **authors**：集合 F1 + false_fill/miss 率分解（本项目把 false_fill 当头等事故——生产环境填错作者比漏填更伤信任）；
- **time**：按 gold 精度比较（gold 到日则只比日）+ publish/update 混淆矩阵 + 时区三态（match/missing/mismatch）；
- **content**：字符 3-gram 多重集 F1 + lcs_f1/dup_ratio/num_f1/para_ratio 四个诊断量；
- **拒识**：互斥分母的拒识准确率（应拒识页与正常页分开计）。

## 5. 最优方案的选择论证（效果-成本权衡）

候选终态：
1. **纯规则 v15**（EXTRACT_MODEL 缺省关闭）：dev 指标与 v15 全同（dev 上模型零净触发），ISPRAS 回退至 v9+v11/v14/v15 规则增益（title 0.806 但 publish ~0.35、authors ~0.29）。700+ 页/分、零模型依赖。
2. **规则+门控模型补全 v15**（交付推荐）：ISPRAS publish +0.19、authors +0.05，dev 不变；代价是触发页 ~2s/页与 12GB 常驻内存。
3. 全量模型（未实施）：每页 ~2s（30 页/分），成本 8-20 倍于门控方案，且 v10 证据表明规则高置信字段上模型无增量、只有幻觉风险。

**结论：方案 2 为效果-成本最优**——门控使模型成本精确落在规则失陷页上（dev 11%、ISPRAS 40% 的页面承担全部模型成本），其余页面享受规则速度。生产部署可按吞吐/质量偏好用环境变量切换：批量回填用纯规则，增量精品库开模型补全层。

## 6. 训练方案设计（按任务要求：只设计、不训练）

### 6.1 路线 A：分类头 IE 模型（优先推荐——用户补充方向，速度导向）

**问题定位**：当前两类残余失分案例 是规则/LLM 都不擅长的「逐块二分类」问题——
①正文段落级取舍（oup 15K 字壳：正文碎成逐段 `<p>`，容器级选择无解，v13 已证）；②署名/时间块的语义确认（块是 byline 还是分享按钮/推荐位）。

**数据构造**：
- 块级标注集：以本项目 117 页 gold + ISPRAS 160 页为源，DOM 块（p/div/li/figure）为单位自动银标——块文本与 gold content 的 3-gram 重合度 >0.5 为正例、<0.05 为负例，中间带人工复核（预计 3-5 万块，人工复核约 10%）；
- 按站点族划分训练/验证/测试（模板隔离，与本项目 dev/test 同纪律）；
- 负例过采样导航/推荐/页脚块（线上分布的难负例）。

**模型架构**：
- 基座：多语小型 encoder（mDeBERTa-v3-base / XLM-R-base，~300MB，CPU 可推理）；
- 输入：块文本（截 256 tok）+ 结构特征拼接（标签路径深度、链接密度、块序位置、字号 class 信号、是否图说——约 16 维手工特征，与文本 [CLS] 拼接）；
- 头：二分类（正文/非正文）；署名与时间各一个同款头（三任务可共享 encoder 多头训练）；
- 推理：逐块前向，正向块按文档序拼接装配——与现有 assemble_container 无缝衔接。

**训练流程**：银标预训练 2-3 epoch → 人工复核子集微调 1 epoch → 按站点族 k-fold 验证 → 块级 F1 与页级 content F1 双指标验收（门槛：页级不低于 v15 traf 链，才允许替换）。
**预期收益**：oup 类壳页 content 0.09→0.9+；ISPRAS content 0.761→估 0.85+；推理 ~5ms/页（CPU 批推理），比 大模型补全快 ~400 倍，可全量开启替代门控。

### 6.2 路线 B：小型 LLM 蒸馏/微调（备选——通用性导向）

**问题定位**：Qwen2.5-7B 零样本在门控场景已够用，但 2s/页与 12GB 常驻是边缘部署瓶颈；且裁决类判断（h1 vs og 标题二选一）与标注口径不一致（v14 负结果）——零样本模型不懂本任务的口径。

**数据构造**：
- 指令样本：以 v10-v15 全部模型调用日志为源——输入（页面文本/候选对）+ 经核验链通过的正确输出（天然带「页内可核验」标签），约 2000+ 条；
- 口径对齐样本：gold 边界分歧挂起项（cnblogs 博客名标题等）按明确口径文档转成指令样本——把「口径」写进训练数据而非指望模型猜；
- 负样本：v10-v13 各轮误填案例（朱先生/观察者网/伪独立行）构造拒答样本。

**模型架构与流程**：Qwen2.5-3B LoRA 微调（秩 16，单卡/统一内存可训），输出保持 JSON schema；训练后过与 v10 相同的核验链（核验链不随模型替换而取消——它是架构的一部分）。
**预期收益**：补全延迟 2s→0.5s/页、内存 12GB→3GB；裁决类场景口径对齐后可重新启用（v14 场景预期 title +0.02~0.04）。

**两路线关系**：A 解决「块级取舍」（规则/LLM 都低效），B 解决「成本与口径」（LLM 已有效但贵）。A 优先——它的目标场景当前完全无解；B 是优化而非补盲。

## 8. 整体不足（诚实清单）

1. **评测**：test 仅 28 页且站点族单一（拒识缺口直到终测才暴露）；ISPRAS 与自建 gold 的口径差异无正式对齐文档，外部基准上的绝对分受口径压制（authors/update 尤甚）；缺人工主观质量抽检环节（指标全对不代表可读）。
2. **指标**：宏平均对「宁缺勿滥」与「宁滥勿缺」不可调——false_fill 与 miss 同权，生产上前者代价通常更高；title 精确匹配对大小写/标点变体过苛（title_sim 只是诊断不入分）；content 3-gram F1 对「多一句少一句」敏感，无法区分「样板混入」与「同义改写」。
3. **数据**：dev 55 个通用页覆盖 11 站，中文门户偏重、英文/小语种/政府站偏薄——v11-v15 的英文策略增量实际由 ISPRAS 驱动发现，dev 无法独立发现它们；gold 边界分歧挂起机制依赖人工登记，累积 11 项未解。
4. **策略**：规则库的 CMS 签名（容器先验/媒体名表）需要随模板演进而维护，存在腐化周期；模型补全层只覆盖 title/authors/publish 三字段，content 依赖 trafilatura 黑盒；拒识判定对「正文极短的真新闻」存在理论上的误拒面。
5. **迭代闭环**：每轮全量重跑 ISPRAS 需 2-5 分钟（模型补全层），迭代后半段成为节奏瓶颈；合成标定（v9）被证明模板覆盖可骗过——标定集本身也需要版本化与扩充流程；探针脚本是一次性的，未沉淀为通用失分案例分析台。
6. **人工参与**：当前人工仅出现在 gold 标注与挂起登记；缺少「人工抽检队列」（按不确定性采样送人工）的常态化设计——模型补全层的核验链能防幻觉，但不能判断「口径对不对」。
7. **上下游**：上游未考虑渲染（needs_render 标记了空壳页但无 headless 渲染臂）、反爬与增量抓取；下游未定义字段的消费者契约（authors 的角色标注粒度、update_time 的业务语义、拒识页的双轨输出）——这些契约会反过来决定 false_fill/miss 的真实代价权重。
