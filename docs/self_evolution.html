04 · Evaluation & Metrics

评测设计与指标设计

数据集分工

  • dev fixed 30：3 个规则站×10 —— 规则库回归基准
  • dev generic 55：11 个通用站×5 —— 调优唯一依据
  • dev negative 4：频道列表页 —— 拒识负例
  • test 28：模板隔离预留（gmw 族，含 8 个应拒识页）—— 交付时一次性、只读聚合
  • ISPRAS 160：80 英文站 —— 跨语言泛化验证，非调优集

评测纪律（全程未破）

  • 调优只看 dev；test 全程仅交付时跑一次聚合
  • 评分器 score_v2 冻结（49 项单测护住口径）
  • gold 不为分数回改——边界分歧挂起登记（cnblogs×11 项）
  • 每轮全量重跑 + 逐页回归 diff；回归即修复或回滚
  • 模型输出必须页内可核验——杜绝幻觉通道

指标口径（v2 冻结）

  • 逐页宏平均；失败永不离开分母（correct_empty 除外）——空 annotation 页猜空得分、猜错扣分
  • authors：集合 F1 + false_fill/miss 分解——false_fill 当头等事故（生产上填错作者比漏填更伤信任）
  • time：按 gold 精度比较（gold 到日则只比日）+ publish/update 混淆矩阵 + 时区三态
  • content：字符 3-gram 多重集 F1 + lcs_f1/dup_ratio/num_f1/para_ratio 四个诊断量
  • 拒识：互斥分母——应拒识页与正常页分开计

06 · Training Plans (Design Only)

训练方案设计（只设计、不训练）

路线 A：分类头 IE 模型优先 · 速度导向

  • 问题定位：规则/LLM 都不擅长的「逐块二分类」——①正文段落级取舍（oup 15K 字壳，正文碎成逐段 <p>，容器级无解，v13 已证）②署名/时间块语义确认
  • 数据构造：117 页 gold + ISPRAS 160 页为源，DOM 块银标（3-gram 重合度 >0.5 正 / <0.05 负），中间带人工复核约 10%（3-5 万块）；按站点族模板隔离切分；难负例（导航/推荐/页脚）过采样
  • 架构：mDeBERTa-v3-base（~300MB，CPU 可推理）+ 结构特征拼接（标签深度/链接密度/块序/字号 class 等 ~16 维）→ 二分类头；三任务（正文/署名/时间）共享 encoder 多头
  • 流程：银标预训练 2-3 epoch → 复核子集微调 → 站点族 k-fold → 块级 F1 与页级 content F1 双门槛验收
  • 预期收益：oup 类壳页 0.09→0.9+；ISPRAS content→估 0.85+；推理 ~5ms/页（CPU），比 LLM 快 ~400 倍，可全量开启替代门控

路线 B：小型 LLM 蒸馏备选 · 通用性导向

  • 问题定位：7B 零样本够用但 2s/页 + 12GB 常驻是边缘部署瓶颈；裁决类判断与标注口径不一致（v14 负结果）——零样本模型不懂本任务口径
  • 数据构造：v10-v15 全部模型调用日志（经核验链通过的正确输出，天然带可核验标签，2000+ 条）+ gold 挂起项按口径文档转指令样本 + 各轮误填案例构造拒答负样本
  • 架构：Qwen2.5-3B LoRA（秩 16，统一内存可训），输出保持 JSON schema
  • 流程：训练后仍过 v10 同款核验链——核验链是架构的一部分，不随模型替换取消
  • 预期收益：兜底延迟 2s→0.5s/页、内存 12GB→3GB；口径对齐后裁决类场景可重新启用（估 title +0.02~0.04）
两路线关系：A 解决「块级取舍」（当前完全无解的场景，补盲）；B 解决「成本与口径」（LLM 已有效但贵，优化）。A 优先。

整体不足（诚实清单）

  1. 评测：test 仅 28 页且站点族单一（拒识缺口直到终测才暴露）；ISPRAS 与自建 gold 口径差异无正式对齐文档；缺人工主观质量抽检。
  2. 指标：false_fill 与 miss 同权，生产上前者代价通常更高；title 精确匹配对大小写/标点过苛；content 3-gram F1 无法区分「样板混入」与「同义改写」。
  3. 数据：dev 中文门户偏重、英文/小语种偏薄——v11-v15 的英文策略增量实际由 ISPRAS 驱动发现，dev 无法独立发现它们。
  4. 策略：CMS 签名库存在腐化周期需维护；content 依赖 trafilatura 黑盒；拒识对「正文极短的真新闻」存在理论误拒面。
  5. 迭代闭环：模型臂全量重跑 2-5 分钟成为后半段节奏瓶颈；合成标定可被模板覆盖骗过（标定集本身也需版本化）；探针脚本一次性，未沉淀为通用分析台。
  6. 人工参与：仅出现在 gold 标注与挂起登记；缺「按不确定性采样送人工」的常态化抽检队列——核验链能防幻觉，不能判断口径。
  7. 上下游：未考虑渲染（needs_render 空壳页无 headless 臂）、反爬与增量抓取；下游字段消费者契约未定义——它反过来决定 false_fill/miss 的真实代价权重。
