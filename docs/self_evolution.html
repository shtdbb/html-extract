规则管线
由站点规则库、元数据解析、trafilatura 通用引擎与 DOM 密度回退构成的确定性抽取链路，单页耗时约 85 毫秒，无外部依赖。
模型补全层
规则管线输出低置信时方才触发的本地大模型补全过程（Qwen2.5-7B，约 2 秒/页）；其输出必须通过页内证据核验方可采纳，否则弃用并回退规则结果。
触发门控
决定单页是否调用模型的判定逻辑：仅当标题缺失或来源过弱、作者为空、发布时间为空，且未被规则层终判为「本站无此字段」时触发。
规则层终判
规则管线对特定站点给出的「该字段不存在」的确定性结论；一经终判，模型补全层同样禁止回填该字段。
误填 / 漏填
误填（false fill）：标注为空而系统给出了值；漏填（miss）：标注有值而系统为空。本方案将误填视为比漏填更严重的事故。
口径挂起项
系统输出与标注答案不一致、但争议点在标注规范本身的条目；登记挂起、不为此修改标注，也不计入策略缺陷。
ISPRAS 基准
俄罗斯科学院系统编程研究所（ISPRAS）公开的英文新闻网页抽取评测集，本项目取 160 页 / 80 站作为跨语言外部基准。

  • dev 通用子集 55 页：11 个通用站点各 5 页——策略调优的唯一依据

  • ISPRAS 外部基准 160 页：80 个英文站点——跨语言泛化验证，不参与调优

评测纪律（全程未破）

  • 调优只看 dev；test 全程仅在交付时做一次聚合评测
  • 评分器冻结（49 项单元测试护住口径，任何修改即失败）
  • 标注答案不为分数回改——边界争议登记为口径挂起项（cnblogs 共 11 项）
  • 每轮全量重评 + 逐页差异比对；出现回归即修复或整体回滚
  • 模型输出必须页内可核验——从机制上杜绝编造通道

指标公式定义

设评测页集 𝒫 = {p₁, …, pN}，单页得分 s(p) ∈ [0,1]，主指标均为宏平均：

S = (1/N) · Σp∈𝒫 s(p)

除「正确判空」外，失败样本永不离开分母：标注为空的页面，系统同样答空方得 1 分，答错记 0 分——防止「空页面一律留空」或「一律猜值」两类投机。

① 标题（精确匹配率）

stitle(p) = 1[ ν(t̂) = ν(t*) ]

t̂ 为系统输出，t* 为标注答案；ν 为规范化函数（去除空白、大小写折叠、全半角归一化）。另有诊断量 title_sim（归一化编辑相似度）用于区分「完全不符」与「后缀型偏差」，仅作分析、不计入总分。

② 作者（集合 F1）

P = |Â ∩ A*| / |Â|    R = |Â ∩ A*| / |A*|    sauthors(p) = 2PR / (P + R)

A* 为标注作者集合，Â 为预测集合；A* 为空且 Â 为空时记 1 分。配套分解指标：误填率（标注为空而预测非空的页面占比）与漏填率（反之）——本方案将误填视为头等事故，生产环境中填错作者比漏填更损害可信度。

③ 时间（按标注精度截断比较）

stime(p) = 1[ trunc(t̂, g) = trunc(t*, g) ],  g ∈ {年, 月, 日, 时, 分, 秒}

g 取标注答案自身的精度：标注精确到日则只比较日期部分，避免「系统多给了时分」反而失分。发布时间与更新时间分别计分，另维护两者的混淆矩阵与时区三态（一致 / 缺失 / 冲突）作为诊断。

④ 正文（字符 3-gram 多重集 F1）

P = Σk min(M̂k, M*k) / Σk M̂k    R = Σk min(M̂k, M*k) / Σk M*k    scontent(p) = 2PR / (P + R)

M̂、M* 分别为预测与标注正文的字符 3-gram 多重集（保留重复计数，对「同一句复制两遍」敏感）。诊断量：LCS-F1（保序程度）、dup_ratio（重复率）、num_f1（数字保真度）、para_ratio（段落结构比）。

⑤ 拒识（互斥分母的拒识准确率）

Acc⁺ = |{p ∈ 𝒫⁺ : 系统拒识 p}| / |𝒫⁺|

𝒫⁺ 为应拒识页面集（图集、列表页等），正常页面集 𝒫⁻ 的误拒率以 𝒫⁻ 为分母另计——两类分母互斥，防止「全部拒识」或「全部接受」抬高单项数字。

停滞判据（v15 终止）：v12 +0.013、v13 零（回滚）、v14 +0.044、v15 +0.025；残余失分簇全部落入四类不可继续区——①任务定义差异（17 页拒识口径分歧）②标注口径差异（更新时间 50 页元数据含 dateModified 而不标）③误填风险区（14 页标注为空但页面有可见日期）④段落级正文取舍，属分类头模型适用场景（按任务要求仅设计训练方案、不实际训练）。
06 · Training Plans (Design Only)

训练方案设计（仅设计，不实际训练）

路线 A：分类头信息抽取模型优先 · 速度导向

  • 问题定位：规则与大模型都不擅长的「逐块二分类」——①正文段落级取舍（个别页面正文碎为逐段独立元素，容器级选择无解，v13 已证）②署名与时间块的语义确认（区分署名行与分享按钮、推荐位）
  • 数据构造：以本项目 117 页标注与 ISPRAS 160 页为源，按 DOM 块自动银标——块文本与标注正文的 3-gram 重合度高于 0.5 为正例、低于 0.05 为负例，中间带人工复核约 10%（预计 3–5 万块）；按站点族做模板隔离切分；对导航、推荐位、页脚等难负例过采样
  • 模型架构：多语小型编码器（mDeBERTa-v3-base，约 300MB，CPU 可推理）；输入为块文本（截断 256 token）与约 16 维结构特征（标签深度、链接密度、块序位置、样式类名信号等）拼接；输出二分类头，正文 / 署名 / 时间三任务共享编码器多头训练
  • 训练流程：银标预训练 2–3 轮 → 人工复核子集微调 → 按站点族 k 折验证 → 块级 F1 与页级正文 F1 双指标验收（页级不低于现有方案方允许替换）
  • 预期收益：碎正文壳页从 0.09 提升至 0.9 以上；ISPRAS 正文预计升至 0.85 以上；推理约 5 毫秒/页（CPU 批推理），较大模型方案快约 400 倍，可全量开启、取代触发门控

路线 B：小型大模型蒸馏备选 · 通用性导向

  • 问题定位：7B 模型零样本已够用，但 2 秒/页与 12GB 常驻内存构成边缘部署瓶颈；且候选裁决类判断（两个候选标题二选一）与标注口径不一致（v14 负结果）——零样本模型不了解本任务的标注口径
  • 数据构造：v10–v15 全部模型调用日志中经核验链通过的正确输出（天然附带「页内可核验」标签，2000 余条）+ 口径挂起项按明确口径文档转为指令样本 + 各轮误填案例构造拒答负样本
  • 模型架构：Qwen2.5-3B + LoRA 微调（秩 16，统一内存可训练），输出保持 JSON 格式约定
  • 训练流程：训练后仍须通过与 v10 相同的输出核验链——核验链是架构的组成部分，不随模型替换而取消
  • 预期收益：补全延迟 2 秒→0.5 秒/页、常驻内存 12GB→3GB；口径对齐后裁决类场景可重新启用（预计标题 +0.02~0.04）
两路线的关系：路线 A 解决「块级取舍」——当前完全无解的场景，属于补盲；路线 B 解决「成本与口径」——大模型已有效但昂贵，属于优化。优先实施路线 A。

整体不足（诚实清单）

  1. 评测：test 仅 28 页且站点族单一（拒识缺口直到终测才暴露）；ISPRAS 与自建标注的口径差异无正式对齐文档，外部基准上的绝对分受口径压制；缺少人工主观质量抽检环节（指标全对不代表可读）。
  2. 指标：误填与漏填同权计分，而生产上前者代价通常更高；标题精确匹配对大小写、标点变体过苛（title_sim 仅作诊断不计分）；正文 3-gram F1 对「多一句少一句」敏感，无法区分「模板噪声混入」与「同义改写」。
  3. 数据：dev 通用子集偏重中文门户，英文、小语种与政府站点偏薄——v11–v15 的英文策略增量实际由 ISPRAS 驱动发现，dev 无法独立暴露这些问题；口径挂起机制依赖人工登记，已累积 11 项未解。
  4. 策略：规则库的内容管理系统签名（容器先验、媒体名表）随模板演进而腐化，需要维护周期；正文字段依赖 trafilatura 黑盒；拒识判定对「正文极短的真实新闻」存在理论上的误拒面。
  5. 迭代闭环：模型补全层参与的全量重评需 2–5 分钟，迭代后半段成为节奏瓶颈；合成标定（v9）被证明可被模板覆盖不足骗过——标定集本身也需要版本化与扩充流程；探针脚本为一次性产物，未沉淀为通用的失分分析台。
  6. 人工参与：人工仅出现在标注与口径挂起登记两处；缺少「按不确定性采样送人工复核」的常态化队列——输出核验链能防止编造，但不能判断口径正误。
  7. 上下游：上游未覆盖渲染（空壳页已标记 needs_render 但无无头浏览器渲染环节）、反爬与增量抓取；下游未定义字段消费者契约（作者角色粒度、更新时间的业务语义、拒识页的双轨输出）——这些契约反过来决定误填与漏填的真实代价权重。
